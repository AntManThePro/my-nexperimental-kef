LOAD FILTERS +12 per tap (max 100) · WASH −35 per tap (min 0) · Flow lines turn pink above load 40. Simulator formulas: pressure = 0.40 + load × 0.01 in wc · capture = max(62, 95 − load × 0.22)%.

07.1 System Architecture

A static prototype today, with a clear path to a connected app.

Renders the archive, holds the session and scans QR labels.
↓
[ App ]
Single-file prototype — the app you are using now.
↓
[ Local state ]
Seed data ships in the file; new entries persist in this browser (localStorage) until storage is cleared.
↓
[ QR scanner ]
Opens the passport for the scanned asset.
↓
[ Production target ]
Replace local state with a backend and database, keep the same screens and flows.
  • Public scan route never exposes site address, customer, or personnel data.
  • All writes authenticated, role-level security scoped to organization and site.
  • Evidence stored with content hash for tamper-evidence.

07.3 Role-Based Access Control
RoleCanCannot
Public scannerScan a QR label; view a passportNo log entries; no diagnostics editing
CleanerRecord observations and cleaning evidenceNo repairs, electrical or ESP work
TechnicianRecord observations, diagnostics and service entriesNo role changes; no source edits
Manager / AdminManage assets, sources and rolesNo direct database access

Role is a demo selector in this prototype. In production, roles come from authenticated accounts. Log export (JSON) in 06.2 is available to all staff roles — Cleaner, Technician, and Manager / Admin alike — because it only downloads entries the role can already see; it is not a manager-only power.

07.4 Privacy & QR
  • A QR label encodes only the asset id — no personal data.
  • Scanning opens the public passport view for that asset.
  • Service entries record a role, not a named person.
  • Photos stay in the session unless the user exports them.
  • No analytics, tracking or third-party scripts in the prototype.

Labels are real scannable QR codes pointing to an example domain.

07.5 Roadmap
  • Phase 1 — Foundation Auth, roles and a database; move seed data into tables. Now

08.2 Session // Settings

Roles change the service log and the asset passport. Cleaner can record observations but cannot enter a diagnosis. Public scanner cannot see the service log at all, and sees a minimal passport — asset ID and type only — with a report-a-concern form instead of the full record. The high-voltage ESP diagnostic stays visible to every role, with its safety wording; reading it is not doing the work. Manager / Admin sees exactly what Technician sees in this prototype — no manager-only view yet. The service-log JSON export (06.2) is available to every staff role — Cleaner, Technician, and Manager / Admin — and only downloads what the role can already see; it is not a manager-only power. See the RBAC table in Blueprint (07.3) for what a production manager could do.

Storage: Local session in this browser (localStorage). No database connected; entries survive reloads until browser storage is cleared.
